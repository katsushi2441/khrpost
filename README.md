# Kurage HR Post（khrpost）

**職（ポジション）を主役にした、職務・職責・目標・タスクの管理。**

「品質管理責任者」「個人情報保護管理者」のような職に、職務・職責・目標がぶら下がり、その目標に対して日々のタスクを記録する。担当者が代わっても記録は職に残るので、後任は前任の記録を読むだけで職を理解できる。

- 1ファイルPHP + SQLite。レンタルサーバーにアップロードするだけで動く
- PHP 7.0 以上 / `pdo_sqlite`
- デモ: https://proto.exbridge.jp/khrpost/

---

## 設置

1. `public/khrpost.php` と `public/khrpost_assets/` をサーバーに置く
2. `public/khrpost_config.php.example` を `khrpost_config.php` にコピーして編集する
3. **社員マスタを用意する**（下記）
4. ブラウザで `khrpost.php` を開く

パスワードは `khrpost_config.php` に書く。リポジトリには実値を入れないこと。

## 社員マスタは khrpost の外に置く

khrpost は社員を持たない。誰が在籍しているかは会社の情報であって、職の管理システムが二重に抱えると必ずズレる（退職者が残る・氏名が食い違う）。

`khrpost_config.php` の `KHP_EMPLOYEES_DIR` に、`employees.json` があるディレクトリを指定する。用意のしかたは2通り。

### A. Kurage Vibe Groupware Core（kvgwc）を使う

kvgwc の `kvgwc_data` のパスを指定するだけ。社員の追加・退職処理は kvgwc 側で行い、khrpost は読むだけになる。

```php
define('KHP_EMPLOYEES_DIR', '/path/to/kvgwc/kvgwc_data');
```

### B. kvgwc を使わず、自分で JSON を用意する

同じ形式のファイルを置けばよい。既存の人事台帳や CSV から書き出す小さなスクリプトを、バイブコーディングで作れば済む。

```json
{"employees":[
  {"id":"e1","no":"E001","name":"山田 太郎","status":"active"},
  {"id":"e2","no":"E002","name":"佐藤 花子","status":"active"}
]}
```

| キー | 意味 |
|---|---|
| `id` | 社員を一意に識別する文字列。任命と記録者がこれで紐づくので、**後から変えないこと** |
| `no` | 社員コード。担当者ログインのID |
| `name` | 氏名。画面に出る |
| `status` | `active` 以外（休職・退職）はログインできない。**退職者もマスタから消さない**（消すと過去の記録の記録者名が出なくなる） |

余分なキーがあっても無視されるので、kvgwc の employees.json をそのまま渡せる。
ファイルが無いときは、設置手順を出す画面が表示される。

## 使い方

| 画面 | 誰が | 何をする |
|---|---|---|
| ホーム | 全員 | 職の一覧。空席の職に警告が出る |
| 職 | 担当者・管理者 | 職務・職責・目標の一覧と、登録・編集・削除。歴代の担当者から前任の記録を開ける |
| タスク | 担当者・管理者 | その目標に対する「やること／やったこと」の記録 |
| 任命 | 管理者のみ | いつから誰がその職か。任命の終了と履歴 |

ログインは2種類。

- **管理者** … 社員コードを空欄にして `KHP_PASSWORD` を入力
- **担当者** … 社員コード（`no`）＋ `KHP_STAFF_PASSWORD` を入力。任命された自分の職しか触れない

### 入力を減らす仕組み

登録フォームには「入力」と「これまでの記録からコピー」のタブがある。参照タブには**前任を含む過去の記録**が日付・記録者つきで並び、「コピー」を押すと入力欄へ転記される。定型のタスクや、前任が書いた職務・職責・目標をそのまま引き写して、違うところだけ直せばよい。

### 達成率の計算

コードが決定的に計算する。AIに採点させない。

- 実績 ＝ その目標のタスクのうち、**「やったこと」が書かれている件数**
- 達成率 ＝ 実績 ÷ 目標値（上限は `KHP_RATE_CAP`、既定120%）
- 職スコア ＝ 目標値のある目標の達成率の単純平均
- 等級 ＝ `KHP_GRADE_TABLE`（既定 S:110, A:100, B:85, C:70、下回れば D）

## データ

`KHP_DATA_DIR`（既定 `khrpost_data/`）に SQLite ファイルを置く。同じ場所に `Deny from all` の `.htaccess` を自動生成するが、**公開ディレクトリの外に置ければなお良い**。

テーブルは4つだけ。

| テーブル | 中身 |
|---|---|
| `posts` | 職。人がいなくても存在する |
| `assignments` | 任命。いつからいつまで誰がその職か（履歴） |
| `duties` | 職務・職責・目標（常に3つ一緒に登録する1行） |
| `tasks` | やること／やったこと。記録者が残る |

## 開発

```bash
php scripts/check_khrpost.php     # 自己テスト（ブラウザ不要）
php scripts/seed_demo.php <dir>   # デモ用サンプルデータを生成
bash scripts/deploy_demo.sh       # 自己テスト → シード → デモ公開
```

自己テストが通ることがデプロイの前提条件。`deploy_demo.sh` は失敗したら公開しない。
